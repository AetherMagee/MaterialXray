Material Xray works with the subscription formats and headers that common panels already produce, including the Happ-compatible extensions. This section covers what the client sends, what it understands, and how to hand a subscription to a user in one tap.

## How a refresh works

1. The client requests your URL with its [request headers](/docs/providers/request-headers/). With **JSON first** on (the default), it tries `<url>/json` first and falls back to the URL itself.
2. It reads [response headers](/docs/providers/response-headers/), along with any `#key: value` [body comments](/docs/providers/response-headers/#body-comments).
3. It parses the body as Xray JSON, a plain share-link list, or base64. See [subscription format](/docs/providers/subscription-format/).
4. It applies metadata, then [routing](/docs/providers/routing-header/) and [per-app rules](/docs/providers/per-app-routing/) if the user's routing policy allows it.

:::note
Refreshes require HTTPS unless the user turns on **Allow insecure updates** for the subscription. Redirects from HTTPS to plain HTTP are refused.
:::
